# GUSI Blog Static Prerendering and Real 404 Fix

## Project

GUSI Website
Production domain: https://gusi.nyc

## Current Status

The initial direct routing problem has been resolved.

The live article now returns:

```text
HTTP/2 200
```

Direct access also works in a private browser:

```text
https://gusi.nyc/blog/hummus-vs-baba-ganoush
```

However, additional testing exposed two remaining technical SEO problems.

## Problem 1: The Initial HTML Is Still the Homepage

Running:

```bash
curl https://gusi.nyc/blog/hummus-vs-baba-ganoush
```

returns the generic homepage HTML rather than article specific HTML.

The initial HTML currently contains:

```html
<title>GUSI | Modern Eastern European Restaurant in Greenwich Village, NYC</title>
```

It also contains:

```html
<link rel="canonical" href="https://gusi.nyc/">
```

The initial HTML contains homepage Open Graph metadata, homepage structured data, and:

```html
<div id="root"></div>
```

The Hummus vs Baba Ganoush article content is not present in the initial server response.

React replaces the metadata and displays the article only after JavaScript executes.

## Problem 2: Unknown Blog URLs Return 200

The following nonexistent URL currently returns HTTP 200:

```text
https://gusi.nyc/blog/invented-test-article
```

This creates a soft 404.

A nonexistent article must return a real HTTP 404 response.

## Primary Objective

Prerender all valid blog pages into static HTML during the production build and configure Apache to return a real HTTP 404 for nonexistent blog slugs.

Do not replace the existing routing fix until the new behavior has been tested.

## Required Architecture

Use static site generation or build time prerendering for the blog.

Because GUSI blog articles are known before deployment and do not require live server generated content, full runtime server side rendering is unnecessary.

The preferred output for the article is:

```text
dist/blog/hummus-vs-baba-ganoush/index.html
```

The generated file must contain the complete article before JavaScript runs.

React may hydrate the page afterward for navigation and interactive functionality.

## Important Compatibility Requirement

Before implementing, inspect:

```text
package.json
vite.config.*
React Router version
current route structure
current blog data structure
current metadata implementation
current deployment process
```

Do not perform an unnecessary major React Router migration.

Use the least disruptive prerendering implementation compatible with the existing application.

Acceptable approaches include:

1. React Router framework prerendering when the existing application is compatible.
2. A Vite static generation implementation.
3. A custom build time rendering script using ReactDOM server rendering and StaticRouter.
4. Another stable static generation approach that creates complete route specific HTML.

Do not use user agent detection.

Do not serve special content only to Googlebot.

Do not use a paid third party rendering service unless separately approved.

## Real 404 Implementation

Generate a physical custom error page:

```text
dist/404.html
```

The page should match the GUSI design and provide useful links to:

• Home
• Menu
• Blog
• Contact
• Reservations

The page must include:

```html
<meta name="robots" content="noindex, follow">
```

Configure Apache:

```apache
ErrorDocument 404 /404.html
```

Because valid blog posts will be generated as physical directories and HTML files, Apache can distinguish valid articles from invalid blog slugs.

Use logic equivalent to:

```apache
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /

  ErrorDocument 404 /404.html

  # Serve real files and generated directories directly
  RewriteCond %{REQUEST_FILENAME} -f [OR]
  RewriteCond %{REQUEST_FILENAME} -d
  RewriteRule ^ - [L]

  # Unknown blog slugs must return a real 404
  RewriteRule ^blog/[^/]+/?$ - [R=404,L]

  # Preserve the React fallback for remaining application routes
  RewriteRule ^ index.html [L]
</IfModule>
```

Confirm this configuration works correctly with the actual server.

Do not blindly copy the rules if the hosting environment requires a variation.

## Client Side Unknown Article Handling

The React application must also handle invalid slugs reached through client side navigation.

When `/blog/:slug` does not match an article:

• Do not display another article
• Do not display the homepage
• Do not display an empty screen
• Display the GUSI Not Found experience
• Add `noindex` to the rendered page

Where practical, navigate to the server backed `/404.html` page so a reload returns a real HTTP 404.
