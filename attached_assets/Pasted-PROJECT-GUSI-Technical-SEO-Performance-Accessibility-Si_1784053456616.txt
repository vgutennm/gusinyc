SECTION 6

PERFORMANCE OPTIMIZATION

The current Lighthouse results supplied for review show:

Mobile performance: 62
Desktop performance: 84
Mobile Largest Contentful Paint: 55.2 seconds
Mobile First Contentful Paint: 4.7 seconds
Approximate page payload: 10.8 MB to 10.9 MB

Investigate the actual Lighthouse trace before making assumptions.

First identify:

1. The mobile Largest Contentful Paint element.

2. The exact asset or request responsible for the delayed LCP.

3. The largest image, video, font and JavaScript payloads.

4. Render blocking CSS and JavaScript.

5. JavaScript that is unused on the homepage.

6. Resources with inefficient browser cache lifetimes.

7. Any third party script delaying rendering.

IMAGE OPTIMIZATION

1. Convert oversized photographic images to modern formats such as WebP or AVIF where browser support permits.

2. Preserve high quality source images.

3. Generate appropriately sized responsive image variants.

4. Use srcset and sizes for responsive image delivery.

5. Do not serve a full desktop image to small mobile screens when a smaller version is sufficient.

6. Set explicit width and height attributes or aspect ratio values to prevent layout shifts.

7. Lazy load images below the first viewport.

8. Do not lazy load the primary LCP image.

9. Give the LCP image high fetch priority when appropriate.

10. Preload the LCP image only after confirming it is the actual LCP resource.

11. Ensure mobile users do not download unused hidden desktop background images.

12. Preserve image alt text.

13. Do not visibly degrade restaurant photography.

JAVASCRIPT OPTIMIZATION

1. Remove unused application JavaScript where safe.

2. Split route specific or feature specific code where practical.

3. Defer noncritical scripts.

4. Delay optional third party functionality until needed where doing so will not break analytics, reservations or consent requirements.

5. Do not remove Google Analytics or Google Tag Manager.

6. Do not load heavy gallery, player, reservation, map or animation code before the user reaches or interacts with the associated component unless required.

7. Confirm that the OpenTable widget and music player still function.

CSS AND FONT OPTIMIZATION

1. Reduce render blocking resources.

2. Inline only genuinely critical CSS when appropriate.

3. Load noncritical CSS without delaying the initial render.

4. Remove unused CSS only after visual regression testing.

5. Use font display swap for locally served web fonts where appropriate.

6. Preload only fonts used above the fold.

7. Avoid preloading every font weight.

CACHING AND COMPRESSION

Configure production cache behavior where supported.

1. Fingerprinted JavaScript, CSS, images and fonts should use long cache lifetimes.

2. HTML should remain revalidatable so updates are visible.

3. Enable Brotli or gzip compression for text resources where supported.

4. Do not cache mutable HTML for a year.

5. Do not apply immutable caching to files that can change without a filename change.

PERFORMANCE ACCEPTANCE TARGETS

Treat these as targets rather than guarantees because Lighthouse scores can vary between runs.

Mobile target:

Performance score of at least 80
Largest Contentful Paint below 3.5 seconds in the controlled Lighthouse test
Cumulative Layout Shift below 0.1
Total Blocking Time below 200 milliseconds

Desktop target:

Performance score of at least 90
Largest Contentful Paint below 2.5 seconds
Cumulative Layout Shift below 0.1

Run at least three tests after deployment and report the median result.

Provide before and after screenshots or shareable PageSpeed reports.

ACCESSIBILITY CORRECTIONS

The audit reports an accessibility score of 93 and identifies two primary issues.

VIEWPORT

Remove any viewport setting that blocks zooming.

Do not use:

user-scalable=no
maximum-scale=1

Use an accessible viewport configuration such as:

width=device-width, initial-scale=1

Users must be able to zoom the website.

COLOR CONTRAST

Identify the exact elements failing contrast requirements.

Adjust only the required foreground or background colors.

Requirements:

1. Preserve the GUSI visual identity.

2. Meet WCAG AA contrast wherever reasonably possible.

3. Pay special attention to small text, muted gold text, buttons, captions and footer links.

4. Do not globally change the entire color palette.

5. Test normal, hover, focus and disabled states.

6. Provide a list of every adjusted element.

LINK PURPOSE

Review identical link text such as Reserve, Menu, Contact or Learn More.

Ensure that links with identical accessible names lead to the same purpose or receive context appropriate accessible labels.
