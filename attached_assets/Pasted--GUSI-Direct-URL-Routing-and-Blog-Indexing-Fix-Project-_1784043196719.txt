# GUSI Direct URL Routing and Blog Indexing Fix

## Project

GUSI Website
Production domain: https://gusi.nyc

## Issue Summary

The following blog page works when visitors navigate to it from within the website:

https://gusi.nyc/blog/hummus-vs-baba-ganoush

However, when the same URL is opened directly in a new browser session, Incognito window, search crawler, or external link, the server returns:

404 Not Found

This is a server routing problem affecting the React single page application.

Googlebot accesses pages through direct URL requests. Therefore, the current server behavior may prevent Google from crawling and indexing blog pages, even when the pages:

• Appear in the XML sitemap
• Contain a canonical URL
• Use index,follow directives
• Work through internal website navigation

## Primary Objective

Configure the production server and React application so all valid public routes return the correct page when accessed directly.

Valid routes must return an HTTP 200 status and must not return a server generated 404 response.

This includes:

• `/blog`
• `/blog/hummus-vs-baba-ganoush`
• All existing blog post routes
• All future blog post routes
• All other valid React routes on the website

## Technical Background

The website uses React with Vite and is deployed to a production web server.

React Router handles routing inside the browser after the application loads. However, when a visitor requests a nested URL directly, the web server looks for a matching physical file or directory.

For example, the server may look for:

`/blog/hummus-vs-baba-ganoush/index.html`

Because that physical file does not exist, the server returns a 404 before React Router has a chance to load.

The server must fall back to the main React application entry file for valid application routes.

## Required Implementation

### 1. Configure Server Routing Fallback

Configure the production server so requests that do not match a real file or directory are served through:

`/index.html`

React Router must then resolve the requested route and display the correct page.

Do not redirect every request to the homepage URL.

The browser URL must remain unchanged.

Correct behavior:

Visitor requests:

`https://gusi.nyc/blog/hummus-vs-baba-ganoush`

Server returns the React application through `index.html`.

React Router displays the Hummus vs Baba Ganoush article.

The address bar remains:

`https://gusi.nyc/blog/hummus-vs-baba-ganoush`

### 2. Apache and cPanel Configuration

The production deployment uses cPanel and may use Apache.

Add or update the `.htaccess` file in the website document root.

Use the following configuration:

```apache
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /

  # Preserve access to existing files and directories
  RewriteCond %{REQUEST_FILENAME} -f [OR]
  RewriteCond %{REQUEST_FILENAME} -d
  RewriteRule ^ - [L]

  # Send all other application routes to React
  RewriteRule ^ index.html [L]
</IfModule>
```

Confirm that:

• `.htaccess` is included in the deployed production files
• Apache `mod_rewrite` is enabled
• The server permits `.htaccess` rewrite rules
• The deployment process does not delete or overwrite the file
• The file is located in the same production directory as `index.html`

If the application is deployed inside a subdirectory rather than the domain root, adjust `RewriteBase` and the fallback path accordingly.

### 3. Preserve Real Static Files

The routing fallback must not interfere with real files or directories.

The following must continue loading normally:

• JavaScript bundles
• CSS bundles
• Images
• Fonts
• Favicon files
• `robots.txt`
• XML sitemap files
• Uploaded assets
• Existing API endpoints
• Any verification files used by Google or other services

Requests for existing files must be served directly and must not be rewritten to `index.html`.

### 4. Verify React Router Configuration

Review the React Router configuration and confirm the following routes are explicitly supported:

```jsx
<Route path="/blog" element={<BlogPage />} />
<Route
  path="/blog/hummus-vs-baba-ganoush"
  element={<HummusVsBabaGanoushPage />}
/>
```

If blog posts use a dynamic route, confirm that the route works correctly:

```jsx
<Route path="/blog/:slug" element={<BlogPostPage />} />
```

The application must correctly resolve the slug:

`hummus-vs-baba-ganoush`

Do not rely only on navigation state passed from another page. The article must load correctly when no prior browser state exists.

### 5. Remove Navigation State Dependency

Review the blog post component for any dependency on data passed through:

```javascript
location.state
```

or another temporary client navigation state.

A direct URL request will not contain this state.

The blog post must retrieve its content using the URL slug or another persistent source.

Acceptable options include:

• A local blog content data file
• A static JavaScript or TypeScript blog post registry
• A content management system request
• An API request using the slug
• A generated static content module

Example:

```javascript
const { slug } = useParams();
const post = blogPosts.find((item) => item.slug === slug);
```

The page must not show an empty state merely because the visitor did not arrive through the blog listing page.

### 6. Add a Proper Application Level 404 Page

The server fallback should load React for unknown application paths, but React must still show a proper Not Found page when no valid route exists.

Add or preserve a final wildcard route:

```jsx
<Route path="*" element={<NotFoundPage />} />
```

Valid routes must show the requested content.

Invalid routes must show the branded GUSI Not Found page.

Do not display the homepage for nonexistent URLs.

Examples:

Valid:

`/blog/hummus-vs-baba-ganoush`

Result: Article page

Invalid:

`/blog/this-article-does-not-exist`

Result: GUSI Not Found page

### 7. HTTP Status Requirements

Verify the production response status for direct requests.

The valid article URL must return:


```bash

```

```text

```

```text

```

The response must not return:

• 301 redirect to the homepage
• 302 redirect to the homepage
• A server error
• A blank document

Also test:

```bash

curl -I https://gusi.nyc/story
curl -I https://gusi.nyc/contact
```

Every valid route must return a successful response.

## Important Limitation

This routing fix will cause the web server to return the React application shell with HTTP 200 for valid application routes.

Because this is a client rendered React site, the first server response may still contain generic application HTML rather than the complete article body.

The routing fix resolves the immediate 404 crawl failure. However, server side rendering, static generation, or prerendering would provide stronger SEO reliability because search engines and AI crawlers could receive the full article content in the initial HTML response.

Do not convert the entire website architecture as part of this fix unless separately approved.

Document whether the article content is present in the initial HTML response or inserted only after JavaScript loads.
